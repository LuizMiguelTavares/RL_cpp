# Project Structure

This document describes the main files and directories in `RL_cpp`.

The project is organized around a C++ training core, JSON configuration files, helper scripts, and external Python-based visualization.

---

## Top-Level Layout

Typical repository layout:

```text
RL_cpp/
├── include/
├── src/
├── tools/
├── scripts/
├── docs/
├── runs/
├── build/
├── CMakeLists.txt
├── config.json
├── build.json
├── animation.json
├── README.md
└── HANDOFF.md
```

## `include/`

The `include/` directory contains public C++ headers.

```text
include/
├── checkpointing.hpp
├── config.hpp
├── episode.hpp
├── gridworld.hpp
├── logging.hpp
├── mc_agent.hpp
├── plot_export.hpp
├── training.hpp
└── types.hpp
```

### Main headers

| File | Purpose |
|---|---|
| `types.hpp` | Basic shared types such as states/actions |
| `gridworld.hpp` | GridWorld environment interface |
| `episode.hpp` | Episode trajectory data structure |
| `mc_agent.hpp` | Monte Carlo Off-Policy agent interface |
| `training.hpp` | Training loop and training history |
| `logging.hpp` | CSV logging interface |
| `checkpointing.hpp` | Checkpoint save/load interface |
| `config.hpp` | JSON configuration structures |
| `plot_export.hpp` | Export helpers for plotting/animation |

```text
src/
```

### Main source files

| File | Purpose |
|---|---|
| `main.cpp` | Program entry point and high-level experiment orchestration |

| `mc_agent.cpp` | Monte Carlo Off-Policy Control implementation |

| `plot_export.cpp` | Exporting GridWorld/Q-table data for Python |

## `tools/`

The `tools/` directory contains auxiliary C++ executables.

```text
tools/
└── export_snapshots.cpp
```

### `export_snapshots.cpp`

Builds the executable:

```text
build/bin/rl_export_snapshots
```

It reads numbered checkpoints:

```text
runs/<run_name>/checkpoints/ep_N/
```

and exports them to:

```text
runs/<run_name>/animation_data/
```

This is used by the Python animation workflow.

## `runs/`

The `runs/` directory stores experiment outputs.

Example:

```text
runs/
└── run_001/
    ├── checkpoints/
    ├── export/
    ├── animation_data/
    ├── figures/
    └── train_history.csv
```

### `checkpoints/`

Stores:

```text
latest/
ep_N/
```

`latest/` is used for resume.

`ep_N/` directories are numbered snapshots used for visualization and analysis.

### `export/`

Stores the final exported state:

```text
grid_map.json
q_table.csv
```

### `animation_data/`

Stores exported checkpoint snapshots for animation:

```text
manifest.csv
ep_0000000500/
ep_0000001000/
...
```

### `figures/`

Stores generated plots and animations:

```text
value_policy_animation.mp4
```

## CMake Organization

The CMake setup builds a shared internal library and two executables.

Conceptually:

```text
rl_core
├── gridworld
├── mc_agent
├── training
├── logging
├── checkpointing
├── config
└── plot_export

rl_main
└── main.cpp

rl_export_snapshots
└── tools/export_snapshots.cpp
```

This avoids duplicating source files between the main executable and the snapshot exporter.

---

## Main Program Flow

The main executable:

```text
build/bin/rl_main
```

does the following:

1. parse command-line arguments;
2. load `config.json`;
3. create the run directory;
4. create or resume the environment and agent;
5. train for `episodes_this_run`;
6. save checkpoints;
7. export final plot data;
8. print greedy path and summary information.

---

## Training Flow

The training loop is implemented in:

```text
src/training.cpp
```

It is responsible for:

- generating episodes;
- updating the Monte Carlo agent;
- collecting metrics;
- writing CSV logs;
- calling the after-episode callback;
- handling graceful stop after the current episode.

The after-episode callback is configured in `main.cpp` and is used for:

- periodic latest checkpoints;
- numbered snapshot checkpoints;
- graceful interruption behavior.
